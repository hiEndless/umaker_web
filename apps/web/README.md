# web

UMAKER public landing page, implemented with Next.js App Router and deployed as a Cloudflare Workers SSR application through OpenNext.

Current scope:

- One public landing page only.
- Current public scope is a single Chinese-first landing page. Multilingual routing was intentionally deferred after the Jarvis template migration.
- Strategy detail pages and public strategy monitor are intentionally out of scope.
- Public metrics are marked as demo or scope indicators, not live performance.
- Particle visuals are semantic topology components. They receive generic nodes and edges, and must not couple directly to strategy or exchange business logic.
- Page reveal motion uses `motion`; scroll narrative sequencing uses `gsap`.
- All animation must respect reduced-motion preferences.

```bash
pnpm --filter @umaker/web dev
pnpm --filter @umaker/web build
pnpm --filter @umaker/web build:worker
pnpm --filter @umaker/web typecheck
```

The local Next build uses `next build --webpack` to keep local and CI builds stable in environments where Turbopack cannot bind its internal IPC endpoint.

Cloudflare Workers output is generated by OpenNext:

```bash
pnpm --filter @umaker/web build:worker
```

Worker output:

```text
apps/web/.open-next/worker.js
apps/web/.open-next/assets
```

Local dev runs on:

```text
http://localhost:8788
```

Preview the Worker locally:

```bash
pnpm --filter @umaker/web preview
```

Deploy to Cloudflare Workers:

```bash
pnpm --filter @umaker/web deploy
```

Future dynamic blog content should be fetched server-side from GitHub in Next.js route handlers, server components, or cached data functions. When ISR or persistent incremental cache is introduced, add explicit Cloudflare KV/R2 bindings and document the cache invalidation strategy.
